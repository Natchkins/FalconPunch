# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Smash Night is a Windows-only Tkinter GUI that browses GameBanana for Super Smash Bros. Ultimate mods and installs them onto a Switch SD card running Atmosphere CFW + ARCropolis. It also handles full Switch provisioning: downloading and laying down Atmosphere/Hekate/Skyline/ARCropolis to the SD, and injecting the fusée/hekate payload over USB via `TegraRcmSmash.exe`.

The entire app lives in one file: `smash_night.py` (~13k lines).

## Run / develop

- Launch normally: double-click `Run.bat` (auto-runs `setup.bat` if `.venv` is missing or built on an unsupported Python), or `.venv\Scripts\pythonw.exe smash_night.py` directly.
- `Smash Night.exe` is a PyInstaller-built *host*, not a bundle: `launcher.py` runs `setup.bat` if `.venv` is missing or on an unsupported Python, then runs `smash_night.py` in its own process on top of the venv (see the taskbar-icon note under layer 8). It must sit next to `smash_night.py`. The same `smash_night.ico` (`APP_ICON`) is the Tk window icon, set with `iconbitmap(default=...)` so every dialog inherits it. `_set_taskbar_icon` additionally loads it at the system large-icon size and sets ICON_BIG via WM_SETICON, because Tk only supplies a 32 px large icon and the taskbar looks soft on high-DPI screens. `main()` first calls `_claim_taskbar_identity()` (SetCurrentProcessExplicitAppUserModelID) — without it Windows groups the window under pythonw.exe and shows the Python icon on the taskbar button regardless of the window icon. That alone is not enough on Windows 11: Explorer takes the *button* icon from a Start-menu shortcut carrying the same AppUserModelID and otherwise falls back to pythonw's icon (the hover preview still shows the window icon). `_ensure_start_menu_shortcut()` therefore keeps `%APPDATA%\\Microsoft\\Windows\\Start Menu\\Programs\\Smash Night.lnk` (target `Smash Night.exe`, else Run.bat; icon `smash_night.ico`; the id in its property store) up to date at every launch; it needs pywin32 (in requirements.txt) and is skipped silently without it. `APP_USER_MODEL_ID` carries a numeric suffix — bump it if Explorer ever caches a stale icon for the id. The decisive fix is the exe itself: a venv's pythonw.exe is a stub that starts the real (Store) pythonw3.12.exe as a *child* process, so branding the stub is useless — the window's process is always pythonw3.12.exe. `Smash Night.exe` (`launcher.py`) therefore *hosts* the app in-process: it asks the venv's python for `sys.base_prefix`, puts that install's Lib / DLLs / Tcl and the venv's site-packages on `sys.path`, and `runpy`s smash_night.py as `__main__`, so the window belongs to an exe whose icon is the emblem. The exe bundles python312.dll and the *entire* stdlib (`build_exe.py`, which `build_exe.bat` runs, passes `--hidden-import` for every `sys.stdlib_module_names` entry — a Python script because the list overflows a cmd variable; `launcher.py`'s `_pyinstaller_deps` lists the extension modules + Tcl/Tk): a Store-installed Python keeps its compiled modules under `C:\Program Files\WindowsApps`, which no other process may load ("DLL load failed … Access is denied"), and a half-bundled package (ctypes without ctypes.util) shadows the base copy and broke PyOpenGL. Search order is app folder → bundle → venv site-packages → base `Lib`; the base `DLLs` folder is never on the path. The app's own packages (numpy, PIL, pyrender…) still come from the venv, so nothing of the app is bundled and the exe is ~18 MB. Interpreter-style args (`-m pip …`, `-c …`) are delegated to the venv's python.exe because the app calls `sys.executable` for pip and helper processes. Run.bat still goes through pythonw and shows the Python icon. The .ico is built from the 96 px icons8 PNG at every size. Rebuild the exe with `build_exe.bat` → `build_exe.py` (installs pyinstaller into the venv, icon from `smash_night.ico`, work files under `%TEMP%\smash_night_build`); the exe is git-ignored as a build product.
- Launch as admin (required for RCM payload injection on systems with UAC fully disabled): double-click `Run_As_Admin.bat`
- There is no test suite, no linter config, no build step. `_test_search.py` is a one-off API probe (and currently imports a stale `gamebanana_browser` module name — broken, do not rely on it).
- **Python must be 3.10–3.12** — `ssbh_data_py` ships no wheels past 3.12, and without it the 3D stack dies and skin installs skip the slot picker (falling back to SSBH Editor). `setup.bat` enforces this: it finds (or winget-installs) Python 3.12, recreates `.venv` if it's on a too-new Python, installs `requirements.txt`, then installs `pyrender` with `--no-deps` (it hard-pins `PyOpenGL==3.1.0`, which modern pip refuses to resolve against the `>=3.1.7` override — never put pyrender back into requirements.txt), and winget-installs WinRAR if no UnRAR is present (`.rar` mods extract as empty husks without it). The in-app `_bootstrap_deps()` / `_bootstrap_unrar()` mirror most of this for people who launch the .py directly.
- `fix_profiles.py` is a one-shot codemod that was run once to inject behavior into `smash_night.py`. It hardcodes a path under `c:\Users\gvopa\...` and is not meant to be re-run. Treat it as historical.

## Releases

Friends get a one-file installer, not the repo. `APP_VERSION` (near `SCRIPT_DIR`) is the app's version; `release.py` builds and publishes:
`build_release.py` makes `release/SmashNight-win64.zip` (PyInstaller **onedir** of `launcher.py` via a generated `release_entry.py` that imports every
third-party package so the numpy/scipy/PIL hooks fire, `--collect-all` for the rest, the whole stdlib as hidden imports, then `smash_night.py` + the resource
folders copied next to the exe — the app resolves everything from `SCRIPT_DIR`, so an installed copy is laid out exactly like the checkout minus `.venv`, and state
files land next to the exe) and `release/SmashNight-Setup.exe` (onefile PyInstaller of `installer.py` with the zip embedded; extracts to
`%LOCALAPPDATA%\Programs\SmashNight`, keeps existing state, makes Desktop + Start-menu shortcuts, launches). `release.py` then tags `v<APP_VERSION>`, creates the
GitHub release on `RELEASES_REPO` with `github_token.txt` and uploads both assets (re-uploading replaces same-named assets). `launcher.py` detects the release layout
(`_internal/` next to the exe, no `.venv`) and skips all venv logic. The in-app **⬆ Update** button (header, after Eject) compares `APP_VERSION` with the newest
release tag (`check_for_update`, checked once ~4 s after start-up; the button turns green with the version when one exists); in an installed release
`_apply_update` downloads `SmashNight-win64.zip`, writes a batch file that waits for the PID to exit, expands the zip and robocopies it over `SCRIPT_DIR`
(no `/MIR`, so profiles / caches / token survive) and relaunches; in a dev checkout it just says to git pull. `release/` is git-ignored. Both assets must exist
in every release or installed copies can't update.

## Voice packs

`voice_packs/build_voice_pack.py` turns a folder of phone recordings into a fighter voice-bank mod: it pairs the Nth take (by the trailing number in the
file name; an unnumbered file is take 1) with the Nth clip in `voice_packs/<fighter>/RECORDING_ORDER.txt`, converts to trimmed/levelled 48 kHz mono WAV
with the venv's ffmpeg, encodes to Switch Opus with `tools/audio/VGAudioCli.exe` (`--opusheader Namco`, 64 kbps CBR — what Ultimate expects), and replaces
every clip by index in a template bank with `tools/audio/nus3audio.exe`, writing `vc_<fighter>_c00…c07.nus3audio` under `voice_packs/<fighter>/out/<name>/`.
The template is any bank with the vanilla clip layout (a GameBanana voice mod works; kept git-ignored under `template/`). Clip names live in the bank's
TNNM chunk; Wii Fit Trainer's 80 are listed in the order file. Work/out folders are git-ignored.

## Local mods

Mods that never came from GameBanana (a voice pack from `voice_packs/`, a friend's folder) are first-class profile entries: the Profiles view's
**Add Local Mod…** button (`_add_local_mod_ui`) drops a menu of the folders already in `local_mods/` plus "Browse for a new folder…" (`_browse_local_mod`); `find_mod_content` checks it is a mod, `register_local_mod` copies it to
`local_mods/<name>/` (git-ignored, the canonical copy) and returns an entry with `mod_id = "local_<name>"`, `mod_type = "local"`, `character` guessed from
`fighter/<x>/` or a `vc_<x>`/`se_<x>` bank name, which `_pick_profile_and_add` puts in a profile. The profile sync needs nothing special: `_do_install_to_sd`
spots the `local_` id, re-stages the folder into `MOD_CACHE_DIR/<id>/extracted/` (`stage_local_mod_in_cache`, so Clear Cache can't lose it) and takes the
stage branch (plain copy, no slot logic) with `.gb_meta.json` carrying the id, so `_scan_installed_mod_ids` sees it and removal works like any mod.
`_download_mod_archive` refuses `local_` ids. Never give a local mod a numeric-looking id.

## Big picture

`smash_night.py` is structured as a long script of module-level helpers followed by a single giant `GameBananaBrowser(tk.Tk)` class that owns all UI. Section banners (`# ── SECTION ──`) are the navigation aid — use `grep -n '^# ──'` to jump.

### Module-level layers (top-to-bottom in the file)

1. **SD-card / path constants** (lines ~70–260). `SD_CARD` is auto-detected from removable + Switch-marker drives; `_apply_sd_drive()` mutates a set of derived globals (`ARCROPOLIS_MODS`, `ATMOSPHERE_CONTENTS`, `PLUGINS_DIR`, `EXEFS_DIR`, `ROMFS_DIR`, `PAYLOAD_SEARCH_PATHS`) when the active drive changes. Anything that touches the SD must read these *globals* (not cache them at import time).
2. **Provisioning profiles + GitHub release map** (lines ~220–290). `PROVISIONING_PROFILES` (Competitive / Skins Only / Custom) layers extra `.nro` plugins on top of `CORE_PLUGINS`. `GITHUB_REPOS` is the source of truth for what to download and how to recognize each asset by filename. Atmosphere has an "unofficial" path: when a new firmware ships, the official repo lags, so we fall back to `UNOFFICIAL_ATMOSPHERE_FORK` (`zandercodes/Atmosphere-unofficial`) for builds of the `22_support` branch, and then to a local zip in `switch_setup/downloads/`.

   ARCropolis has the same lag problem in a sharper form: it hard-refuses any Smash version but the one it was built for, and a new Smash update can leave the fix on `main` unreleased for days (13.0.5 shipped; v4.0.9 was still a 13.0.4 build). `find_local_arcropolis_override()` looks in `switch_setup/downloads/` for a hand-placed `libarcropolis.nro` (or a zip containing one, e.g. a CI artifact) and `_download_plugin_from_github` prefers it over GitHub — which also keeps *Update All* from clobbering it. `arcropolis_required_smash_version()` reads the required Smash version out of any `libarcropolis.nro` (the refusal dialog is embedded as a plain string), and the Setup tab shows it as "built for Smash X" so a mismatch is visible before boot.

   There is deliberately **no nightly / CI-artifact path** any more (removed 2026-11-02 at the user's request: "I do a pinned version. Never nightly."). ARCropolis is always installed from a release — `latest` or a `tag:` pinned in the Setup's Sources — and a hand-placed override in `switch_setup/downloads/` is the only other way in. `github_latest_ci_artifact` / `_install_arcropolis_nightly` / `ARCROPOLIS_CI_BRANCH` are gone; the legacy `nightly_arcropolis` key in old profiles/Setups is ignored on read and dropped on save.

   The mod also reads an optional `sd:/ultimate/ssbu_online_deluxe/config.toml` (menu / offline / online-Auto render profiles, overclocker switch). Each user profile carries its own copy under `deluxe_config` (`DELUXE_CONFIG_DEFAULTS`, normalized by `profile_config()`), both profile dialogs edit it via `_build_deluxe_config_widgets()`, and Provision writes the file through `_write_deluxe_config()` when `deluxe_config_status()` says the card differs. `parse_deluxe_config_toml()` is deliberately tiny — it reads the shape upstream documents and we write, and returns None (→ "rewritten on Provision") for anything else rather than guessing.

   `KNOWN_PLUGINS` is the plugin registry — dispatch on it, not on `LOCAL_PLUGINS` (that's only a fallback *cache* of `.nro` files bundled in this repo, and most plugins have no bundled copy). Two flags matter:
   - `dependency: True` — installed and removed alongside the mod that needs it, never toggled on its own. `expand_plugin_deps()` adds them; `selectable_plugins()` hides them from the profile editor.
   - `deprecated: True` — never installed, but still listed so a card provisioned by an older build is recognised and cleaned up. `RETIRED_PLUGINS` maps each to its replacement, and `migrate_retired_plugins()` translates at *read* time inside `profile_config()` — `gb_profiles.json` is never rewritten, so an older build of the app can still read it.

   **SSBU Online Deluxe** (`saad-script/ssbu-online-deluxe`) replaced Latency Slider DE + Less Delay when SSBU 13.0.5 broke both. It is not a standalone `.nro`: `ONLINE_DELUXE_DEPS` lists six plugins it needs, it pins its *own* Skyline build (`_install_skyline()` takes `main.npdm`/`subsdk9` from the mod's release, because upstream warns the current skyline-dev release crashes with it), and it wants a boot2 overclock sysmodule under `OC_SYSMODULE_TITLE_ID` (`oc_sysmodule_dir()`, `_install_oc_sysmodule()`). A partial install is a guaranteed crash on boot — never let one of these pieces be installed without the others.

   `extract_release_file(repo, filename, dest)` is the single install path for every plugin: it prefers a release asset named exactly `filename`, else searches inside every `.zip` asset for a member with that basename. Match on the *payload* filename, never the asset name — upstream renames release archives between versions far more often than the files inside them. Release archives are cached per run in `_RELEASE_ZIP_CACHE` (the Online Deluxe zip supplies seven files); call `_clear_release_cache()` when a provision/update run finishes.

   **Quickplay build.** Upstream deliberately enables its latency / render-profile controls only in Arena, Local Online and Nextendo-Quickplay (`is_valid_online_mode()` in `src/net/mod.rs`, plus the status store in `online_melee_any_init`). `vendor/ssbu-online-deluxe/` is upstream at a pinned tag with those gates removed — five changes across `src/net/mod.rs`, `src/render/profile.rs` and `src/ui/overlay/mod.rs`, each marked `// Fork:` (the two mode gates; `online_bg_matchmaking_init` no longer resetting Quickplay to Offline during the post-CSS opponent search; `match_init` treating any valid online mode as an online match even before the pia session reports connected — without those two the match started on the *offline* profile, Vanilla; and `reconcile_enforced_vanilla()`, which restores vanilla *resolution* once per match when the closed-source ssbusync has forced the pipeline back to vanilla on Nintendo's servers, and tags the overlay's NetProfile cell "(server)" — ssbusync's override cannot be disabled from the mod, so the label is made honest rather than the profile made to stick; and `suggested_delay_frames()`, which appends "~Nf" to the overlay's Ping cells); its `VENDOR_INFO.md` records the tag/commit, each change, what was dropped from the tree, and the update procedure. It is deliberately a vendored *copy*, not a fork or a patch file, so the mod's Rust can be edited from chat and the build depends on nothing outside this repo. `.github/workflows/build-online-deluxe.yml` builds it in the `jugeeya/cargo-skyline` container on any change under `vendor/ssbu-online-deluxe/` and **commits the resulting `.nro` to `smash_mods/quickplay/`** (with `BUILD_INFO.txt`). `_download_plugin_from_github` *used to* prefer that file (`ONLINE_DELUXE_QUICKPLAY_BUILD`) over upstream's release for the `.nro`; since 2026-11-02 it doesn't — the Online Deluxe source is the Ivan Elite fork (see layer 8) — Skyline, ssbusync, nx-over and the sysmodule are not in the source and keep coming from upstream's release via `ONLINE_DELUXE_REPO_KEY`. `_NRO_TO_REPO[ONLINE_DELUXE_NRO]` still names upstream so the Setup row's version hint tracks the real project. If the file is absent, install falls back to upstream's `.nro`. `lib/libimgui_smash.a` (16 MB) is a required link blob, not an accident. This build cannot be produced in the Claude sandbox (no Docker daemon); the workflow is the only build path.
3. **GameBanana category tables** (~290–560). `FIGHTER_CATEGORIES` (skins, cat 3330), `STAGE_CATEGORIES` (cat 6089), `OTHER_CATEGORIES`, gameplay subcats. `MOD_TYPE_BY_CATEGORY` collapses a GameBanana subcategory id onto a coarse type (`skin` / `stage` / `moveset` / `modpack` / `mechanics` / `balance` / `ai` / `parameters` / `effect` / `music` / `ui` / `other`). Only `skin` mods drive the slot-picker UI (`SLOT_AWARE_MOD_TYPES`).
4. **File-conflict / slot classification** (~700–900, ~2360–2840). `_classify_mod_path(rel_path)` is the most important helper here: it returns `(fighter, slot)` for a relative file path inside a mod and is shared by:
   - `detect_file_conflicts()` — distinguishes *real* per-slot collisions (must remap) from shared-resource overlaps that ARCropolis layers last-write-wins (no prompt).
   - `compute_touched_slots()` — populates `gb_touched_cache.json` after install.
   - `simulate_resolved_layout()` / `diagnose_freeze_risks()` — pre-flight scan that mimics what SSBU's file resolver will see and flags freeze risks (orphan portrait/body, motion without model, multi-mod collisions).
5. **GameBanana API** (~930–1110). `api_search_mods` is the single search path for browse / stages / "Other". `api_get_mod_files` and `api_get_mod_images` round it out. All over `https://gamebanana.com/apiv11`. Network is `requests` with `verify=False` and urllib3 warnings suppressed.
6. **Install pipeline** (~1620–2240). `extract_archive` → `find_mod_content` (locates the romfs root inside the extracted tree) → `install_to_sd` (copies to `<SD>/ultimate/mods/<name>[_cXX]`, writes `.gb_meta.json`, applies optional `slot_map` or `target_slot` remap). `_remap_slots` / `_apply_slot_map` rename `cXX` directories *and* slot-bound filenames (UI bntx, sound nus3audio) consistently. `_repair_multislot_artifacts` cleans up GameBanana archives that ship malformed dirs like `c00, c03`.
7. **RCM injection** (~1640–1830). `inject_payload(smash_exe, payload_path)` has a careful three-branch strategy: (1) if already admin, run subprocess directly; (2) if `EnableLUA=0`, bail with a message pointing at `Run_As_Admin.bat` (Windows can't elevate at all in this state); (3) otherwise, elevate via `ShellExecuteEx` with `SEE_MASK_NOCLOSEPROCESS` and wait on the process handle. Do **not** replace this with PowerShell `Start-Process -Verb RunAs` — signed-script enforcement and ExecutionPolicy break it intermittently with a misleading "operation was canceled by the user" error.
8. **Profiles, Setups + favorites persistence** (~3260–3620). Three related concepts:
   - **User profiles** (`gb_profiles.json`) — curated lists of mods plus `wifi_safe`. These are *cosmetic* only now: the Profiles tab's "Load to SD" delta-syncs a profile's mods onto the card. Older entries still carry core keys (`template`, `unofficial_atmo`, `nightly_arcropolis`, `plugins`, `deluxe_config`); `profile_config()` keeps tolerating them (`plugins=None` = "inherit from template", `[]` = "explicitly none") but nothing reads them for provisioning any more.
   - **Setups** (`gb_setups.json`, `{"active": name, "setups": {name: {...}}}`) — saved *core* configurations the Setup tab deploys: plugin set, fork vs. official Atmosphere, Sources, Online Deluxe `config.toml`. `setup_config()` normalizes one (it is `profile_config()` minus `wifi_safe`). `load_setups()` migrates once: every profile carrying core keys becomes a Setup of the same name, identical configs collapsed, else a single default "Tournament" Setup. The active Setup is persisted in the file; `_active_setup_name()` / `_active_setup_cfg()` / `_set_active_setup()` are the accessors, and `_active_plugin_list()` / `_active_deluxe_config()` read from it. The Setup tab has a Setup chooser combobox, a "Manage Setups…" dialog (`_open_setup_dialog`, with the card-matches-setup banner and a Provision Card button), and Provision runs `_provision_setup(name)`. `SETUP_NOUN` is the user-facing name of the concept; change it there if "Setup" gets renamed. Each Setup can also override **Sources**: `sources` is `{key: {repo, ref}}` for every `GITHUB_REPOS` key; `ref` is `latest`, `prerelease`, `tag:<tag>` or `branch:<name>`. Three rows have non-trivial stock values (Atmosphere, Smashline, Online Deluxe) (`source_default`): **Atmosphere** is `OFFICIAL_ATMOSPHERE_REPO @ latest` (official 1.12.1 supports FW 23.0.0; the fork's 23_support builds are older) — pointing the row at any other repo makes `_resolve_unofficial_atmosphere` prefer that fork's support-branch builds (`ATMOSPHERE_SUPPORT_BRANCH`, now `23_support`, when the ref isn't a `branch:`) when newer than official stable, which is the old fork-Atmosphere flag; **ARCropolis** has no special stock value any more (`latest`; pin a `tag:` to hold a version — there is no CI-build path); **Smashline** is pinned to `tag:v1.6.8` because Smashline 2.0.0 (2026-10-28) breaks plugins built against 1.x, SSBU Online Deluxe included. `setup_config()` derives `unofficial_atmo` from the Atmosphere row and translates the legacy boolean keys and the retired `atmosphere_fork` row into an Atmosphere row on read (a legacy `unofficial_atmo: True` with no row now simply means stock, i.e. official); Manage Setups drops the legacy keys on save. `_active_setup_cfg()` mirrors the active Setup's overrides into the module-level `_SOURCE_OVERRIDES`, and every download / version-check path reads through `source_repo()` / `source_ref()` / `source_release()` / `source_asset()` instead of `GITHUB_REPOS` directly (`github_release_for(repo, ref)` does the tag / prerelease lookups; `source_asset` reports official stable for a branch ref on Atmosphere / fusée and the release for one on ARCropolis). **SSBU Online Deluxe's stock source is a fork**: `IvanSS22030/ssbu-online-deluxe-ivan-elite @ tag:v1.4.2-ivan` (upstream 1.4.1 with the latency / render-profile controls enabled in Nintendo's Quickplay and Elite Smash). That replaced the earlier approaches (the vendored `vendor/ssbu-online-deluxe` build and a short-lived per-Setup "patches" mechanism — both gone from the install path; the vendored tree remains in the repo (its Actions workflow was removed 2026-11-19 — this repo deliberately uses no GitHub Actions) but nothing reads `smash_mods/quickplay/` any more). A fork release is a whole SD layout, so the app indexes the source's package (`source_package_index`, cached per run with the release zip): chain dependencies the package ships are installed from it (`_download_plugin_from_github`, `package_ships`) and judged against it in the health check; bundled-only dependencies the fork leaves out (`_NRO_TO_REPO` → the Deluxe key, e.g. nx-over, which Ivan's build removes) are dropped from `_active_plugin_list()` so they are neither installed nor reported missing; sysmodules are installed under whatever title ids the package uses (`package_sysmodules`, `sysmodule_title_ids` — Ivan ships sys-clk under `00FF0000636C6BFF` plus `config/sys-clk/config.ini`, instead of upstream's overclocker under `OC_SYSMODULE_TITLE_ID`), and `_remove_oc_sysmodule` / the health row follow the same ids. When the package ships a sysmodule but not upstream's `OC_SYSMODULE_TITLE_ID` (`package_overclocker_external()`), the mod's built-in overclocker has no service to reach and shows "Unable to load overclocker service" at launch, so `effective_deluxe_config()` forces `overclocker = false` in the config.toml this app writes (`_active_deluxe_config()` returns the effective config; Manage Setups labels the checkbox as overridden). `package_overclocker_external()` answers from `_PACKAGE_INDEX_CACHE` only when called on the Tk main thread (dialog builds, status labels) — indexing the package can download the release zip, which froze Manage Setups while a GitHub check was running; worker threads resolve it for real. Point the row back at `saad-script/ssbu-online-deluxe @ latest` to get upstream's package. Edited from the Sources… button inside the selected Setup's form in Manage Setups (`_open_sources_dialog`, which shows repos as full github.com links and sizes itself to fit every row); `normalize_repo_text` accepts a link or `owner/name`, and only entries that differ from the defaults are stored (`normalize_sources`). Manage Setups has no Provision button — the Setup tab's Provision deploys the chosen Setup; name edits commit with its Save button. It also holds the **GitHub token** box (`save_github_token` / `github_token_status`, writing the git-ignored `github_token.txt` that `_github_token()` reads; env vars `GITHUB_TOKEN` / `GH_TOKEN` still win). There is no Manage Profiles dialog and no "set active" anywhere: the Create Profile dialog sets name + Wifi-Safe, cards have Duplicate / Delete, and the profile a download lands in is picked per click from each card's **Download ▾** dropdown (`_popup_profile_menu`, which also offers "Create Profile…"); skin cards' Download ▾ opens the 3D / drag-to-slot dialog (`_view_model`; drops write the profile immediately, but the dialog snapshots `gb_profiles.json` on open (`ctx["profile_snapshot"]`) and `_on_install_window_close` restores it unless Save set `ctx["saved"]` — Close / the X mean cancel), while stage / pack / other cards (and non-slot Favorites) have a single registered Download ▾ that installs directly (`_register_install_button`, blue, flips to "✓ In Profile ▾"); that pick becomes `_profile_mode_target` via `_set_profile_target`, which the slot pickers show on their own clickable "Profile: <name> ▾" line above the "Install to:" slot row (two lines so c00–c07 never clip; the circled "?" to the right of the slots (`_add_help_circle`) shows `SLOT_COLOR_HELP` as a left-aligned tooltip or window: grey empty / green taken by another skin / blue this skin). The Setup tab's chooser (unlabelled combobox + Manage Setups… button) and action grid live in `_setup_actions_frame`, a strip packed *above* the results canvas so it never scrolls; the pass/fail summary and check rows scroll beneath it. The grid is 3 equal-weight columns filling the pane: row 0 Provision / red Clean Provision (wipes the SD after confirmation) / Clear All Mods; row 1 Quick Actions / Inject Payload (spanning 2 columns); the pass/fail summary heads the scrolling check list beneath the strip. Check rows are strictly one line each (`_add_check_row`: name on the left, the detail right-aligned, newlines collapsed to ` · `; the detail is a flat read-only `Entry`, not a label, so a long one scrolls left/right (drag, arrows, Shift+wheel) instead of being truncated). `_clean_provision` waits for Windows to re-mount the card after the format (`_wait_for_sd`) and `_provision` re-takes its health snapshot while the SD Card row fails — acting on a snapshot taken before the re-mount installed nothing, which was the "first Clean Provision stays red, second works" bug. The window opens sized so this list needs no scrolling: `_build_ui` estimates the height from the active Setup's component count, and `_fit_window_to_setup()` grows the window to the real content height exactly once (first Setup render, `_setup_fit_done`), both capped at the screen height; later repaints (provision, re-check) never resize the window. Width is ~45% of the screen (min 1600, capped to the screen) and the results pane stays a fixed 860px so extra width goes to the Log; the window is never maximized or shrunk automatically. ### A few non-obvious invariants

- `MAX_SLOT = 16` (c00..c15) is how far to *scan* when reading a card — a c08+ mod someone installed by hand must still be seen and conflict-checked. `VANILLA_SLOTS = 8` is how far this app may *assign*: every site that picks a free slot goes through `assignable_slots()` (c00..c07), and both slot pickers render c08+ greyed and unclickable. Slots c08+ don't exist in `data.arc`; they only work with `new-dir-infos` / `new-dir-infos-base` / `share-to-added` declarations that `_regenerate_config_json` does not generate, so handing one out produces a mod that freezes at match load. Don't reintroduce `range(MAX_SLOT)` in an assigning path.
- `_regenerate_config_json` must never filter `share-to-vanilla` / `share-to-added` by disk existence. Per ARCropolis `fs.rs`, each key is a source *hash* resolved against the arc and each destination is fed to `add_shared_file` precisely when it is *not* already a file — a destination not being on disk is the designed case. Filtering on it deletes every entry and is what made reslotted skins freeze while native-slot installs (which never rewrite `config.json`) kept working. Only `new-dir-files` entries are real mod files and safe to orphan-strip.
- **ARCropolis 4.1+ is two things, not one.** Its release zip ships `libarcropolis.nro` *and* `ultimate/arcropolis/resources/` (menu layouts, `msg_menu.xmsbt`, `config.json`). Install only the `.nro` and every boot shows "ARCropolis is missing files it needs for its in-game menus" (the game still runs, so it's easy to miss). `extract_arcropolis_resources()` lays those members down from whatever archive the plugin came from (release zip, CI artifact, hand-placed zip); `_install_arcropolis_resources()` falls back to the release zip; `_download_plugin_from_github` calls it after every ARCropolis install, and the SD Health row "ARCropolis Menu Files" (`arcropolis_resources_status()`, fix key `arcropolis_resources`) reports it. Never add an ARCropolis install path that skips this.
- `WIFI_UNSAFE_MOD_TYPES` is what gates the wifi-safe profile filter. Everything else (skin/stage/ui/music) is treated as wifi-safe.
- "Slot collision" and "shared overlap" are distinct concepts in this codebase — only the former should ever surface a remap prompt to the user. `_classify_mod_path` returning `(None, None)` means "shared resource, last-write-wins, do not warn".
- When the user picks a different SD drive from the multi-drive prompt at startup, you must call `_apply_sd_drive(drive)` rather than just reassigning `SD_CARD` — there are several derived globals.
- `numpy>=2.0` removed `np.infty`, but `pyrender.Viewer` still references it. There's a shim at the top of the file (`np.infty = np.inf`); leave it in if you touch the imports.
