# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Smash Night is a Windows-only Tkinter GUI that browses GameBanana for Super Smash Bros. Ultimate mods and installs them onto a Switch SD card running Atmosphere CFW + ARCropolis. It also handles full Switch provisioning: downloading and laying down Atmosphere/Hekate/Skyline/ARCropolis to the SD, and injecting the fusée/hekate payload over USB via `TegraRcmSmash.exe`.

The entire app lives in one file: `smash_night.py` (~13k lines).

## Run / develop

- Launch normally: double-click `Run.bat` (auto-runs `setup.bat` if `.venv` is missing or built on an unsupported Python), or `.venv\Scripts\pythonw.exe smash_night.py` directly.
- `Smash Night.exe` is a PyInstaller-built *host*, not a bundle: `launcher.py` runs `setup.bat` if `.venv` is missing or on an unsupported Python, then runs `smash_night.py` in its own process on top of the venv (see the taskbar-icon note under layer 8). It must sit next to `smash_night.py`. The same `smash_night.ico` (`APP_ICON`) is the Tk window icon, set with `iconbitmap(default=...)` so every dialog inherits it. `_set_taskbar_icon` additionally loads it at the system large-icon size and sets ICON_BIG via WM_SETICON, because Tk only supplies a 32 px large icon and the taskbar looks soft on high-DPI screens. `main()` first calls `_claim_taskbar_identity()` (SetCurrentProcessExplicitAppUserModelID) — without it Windows groups the window under pythonw.exe and shows the Python icon on the taskbar button regardless of the window icon. That alone is not enough on Windows 11: Explorer takes the *button* icon from a Start-menu shortcut carrying the same AppUserModelID and otherwise falls back to pythonw's icon (the hover preview still shows the window icon). `_ensure_start_menu_shortcut()` therefore keeps `%APPDATA%\\Microsoft\\Windows\\Start Menu\\Programs\\Smash Night.lnk` (target `Smash Night.exe`, else Run.bat; icon `smash_night.ico`; the id in its property store) up to date at every launch; it needs pywin32 (in requirements.txt) and is skipped silently without it. `APP_USER_MODEL_ID` carries a numeric suffix — bump it if Explorer ever caches a stale icon for the id. The decisive fix is the exe itself: a venv's pythonw.exe is a stub that starts the real (Store) pythonw3.12.exe as a *child* process, so branding the stub is useless — the window's process is always pythonw3.12.exe. `Smash Night.exe` (`launcher.py`) therefore *hosts* the app in-process: it asks the venv's python for `sys.base_prefix`, puts that install's Lib / DLLs / Tcl and the venv's site-packages on `sys.path`, and `runpy`s smash_night.py as `__main__`, so the window belongs to an exe whose icon is the emblem. The exe bundles python312.dll and the *entire* stdlib (`build_exe.py`, which `build_exe.bat` runs, passes `--hidden-import` for every `sys.stdlib_module_names` entry — a Python script because the list overflows a cmd variable; `launcher.py`'s `_pyinstaller_deps` lists the extension modules + Tcl/Tk): a Store-installed Python keeps its compiled modules under `C:\Program Files\WindowsApps`, which no other process may load ("DLL load failed … Access is denied"), and a half-bundled package (ctypes without ctypes.util) shadows the base copy and broke PyOpenGL. Search order is app folder → bundle → venv site-packages → base `Lib`; the base `DLLs` folder is never on the path. The app's own packages (numpy, PIL, pyrender…) still come from the venv, so nothing of the app is bundled and the exe is ~18 MB. Interpreter-style args (`-m pip …`, `-c …`) are delegated to the venv's python.exe because the app calls `sys.executable` for pip and helper processes. Run.bat still goes through pythonw and shows the Python icon. The .ico is built from the 96 px icons8 PNG at every size. Rebuild the exe with `build_exe.bat` → `build_exe.py` (installs pyinstaller into the venv, icon from `smash_night.ico`, work files under `%TEMP%\smash_night_build`); the exe is git-ignored as a build product.
- Launch as admin (required for RCM payload injection on systems with UAC fully disabled): double-click `Run_As_Admin.bat`
- There is no test suite, no linter config, no build step. `_test_search.py` is a one-off API probe (and currently imports a stale `gamebanana_browser` module name — broken, do not rely on it).
- **Python must be 3.10–3.12** — `ssbh_data_py` ships no wheels past 3.12, and without it the 3D stack dies and skin installs skip the slot picker (falling back to SSBH Editor). `setup.bat` enforces this: it finds (or winget-installs) Python 3.12, recreates `.venv` if it's on a too-new Python, installs `requirements.txt`, then installs `pyrender` with `--no-deps` (it hard-pins `PyOpenGL==3.1.0`, which modern pip refuses to resolve against the `>=3.1.7` override — never put pyrender back into requirements.txt), and winget-installs WinRAR if no UnRAR is present (`.rar` mods extract as empty husks without it). The in-app `_bootstrap_deps()` / `_bootstrap_unrar()` mirror most of this for people who launch the .py directly.
- `fix_profiles.py` is a one-shot codemod that was run once to inject behavior into `smash_night.py`. It hardcodes a path under `c:\Users\gvopa\...` and is not meant to be re-run. Treat it as historical.

## Releases

Friends get a one-file installer, not the repo. `APP_VERSION` (near `SCRIPT_DIR`) is the app's version; `release.py` builds and publishes:
`build_release.py` makes `release/SmashNight-win64.zip` (PyInstaller **onedir** of `launcher.py` via a generated `release_entry.py` that imports every
third-party package so the numpy/scipy/PIL hooks fire, `--collect-all` for the rest, the whole stdlib as hidden imports, then `smash_night.py` + the resource
folders copied next to the exe — the app resolves everything from `SCRIPT_DIR`, so an installed copy is laid out exactly like the checkout minus `.venv`, and state
files land next to the exe) and `release/SmashNight-Setup.exe` (onefile PyInstaller of `installer.py` with the zip embedded; extracts to
`%LOCALAPPDATA%\Programs\SmashNight`, keeps existing state, makes Desktop + Start-menu shortcuts, launches). `release.py` then tags `v<APP_VERSION>`, creates the
GitHub release on `RELEASES_REPO` with `github_token.txt` and uploads both assets (re-uploading replaces same-named assets). `launcher.py` detects the release layout
(`_internal/` next to the exe, no `.venv`) and skips all venv logic. The in-app **⬆ Update** button (header, after Eject) compares `APP_VERSION` with the newest
release tag (`check_for_update`, checked once ~4 s after start-up; the button turns green with the version when one exists); in an installed release
`_apply_update` downloads `SmashNight-win64.zip`, writes a batch file that waits for the PID to exit, expands the zip and robocopies it over `SCRIPT_DIR`
(no `/MIR`, so profiles / caches / token survive) and relaunches; in a dev checkout it just says to git pull. `release/` is git-ignored. Both assets must exist
in every release or installed copies can't update. Every release after the first goes through `release.py --bump patch|minor|major` (raises `APP_VERSION`,
commits and pushes it, then builds and publishes); `release.py` refuses to publish when the tag already exists on an older commit, so a version is never
reused for new code. The token in `github_token.txt` must be a fine-grained one with *Contents: Read and write* on `RELEASES_REPO`.
**No `.exe` is tracked in git** (`*.exe` is git-ignored since 2026-11-19, at the user's request): the bundled tools (TegraRcmSmash + APX driver installer,
UnRAR, VGAudioCli, nus3audio) live on disk only and reach users through the release build, which copies them from the working folder — a fresh clone
does not have them, so releases must be built from a folder that does. `build_release.py`'s `EXCLUDE` keeps TegraRcmGUI's unused extras (`favorites/`,
`tools/`, its log and presets — the same list `.gitignore` withholds) out of the release. `launcher.py` treats a leading `smash_night.py` argument as the
app starting a second copy of itself, so `Smash Night.exe smash_night.py --view-model <dir>` (the interactive 3D viewer subprocess) runs the app; only a
dashed first argument *without* that prefix (`-m pip`, `-c`) is an interpreter call (delegated in dev, a no-op in a release).

## Voice packs

`voice_packs/build_voice_pack.py` turns a folder of phone recordings into a fighter voice-bank mod: it pairs the Nth take (by the trailing number in the
file name; an unnumbered file is take 1) with the Nth clip in `voice_packs/<fighter>/RECORDING_ORDER.txt`, converts to trimmed/levelled 48 kHz mono WAV
with the venv's ffmpeg, encodes to Switch Opus with `tools/audio/VGAudioCli.exe` (`--opusheader Namco`, 64 kbps CBR — what Ultimate expects), and replaces
every clip by index in a template bank with `tools/audio/nus3audio.exe`, writing `vc_<fighter>_c00…c07.nus3audio` under `voice_packs/<fighter>/out/<name>/`.
The template is any bank with the vanilla clip layout (a GameBanana voice mod works; kept git-ignored under `template/`). Clip names live in the bank's
TNNM chunk; Wii Fit Trainer's 80 are listed in the order file. Work/out folders are git-ignored.

## Setup types

Every Setup has a `type` (`SETUP_TYPES`, chosen from the **Type** dropdown in Manage Setups, which replaced the per-plugin checkboxes): **Competitive Online**
(SSBU Online Deluxe + its chain, Smashline pinned 1.6.8), **TR4SH Rebuffed** (NRO Hook + Smashline, both from their own repos, + the TR4SH pack from a profile) and **Skins Only**. A type fixes the
plugin set (`setup_type_plugins`), supplies source rows that apply unless the Setup's own Sources override them (none of the three types needs one today — see the Smashline note below), and may own a
*pack* (`SETUP_PACKS`). `setup_type()` infers the type of a pre-types Setup from its `plugins` (Online Deluxe ticked → Competitive Online, else Skins Only);
`setup_config()` returns `type` / `pack` and the type's plugins, and `_active_profile` now carries the type name for messages. **Smashline: TR4SH uses the same pinned v1.6.8 as everything else.** "Smashline 2" in TR4SH's instructions is the *name* of the HDR-Development/smashline project (successor of the old Smashline 1 plugin); its releases are numbered 1.x (v1.6.7 = 13.0.5 support, v1.6.8 = a crash fix). The repo's **v2.0.0** (2026-10-28) requires a new `ozone` dependency and breaks mods built against 1.x — TR4SH 1.46 (2026-10-02) included. The first version of the TR4SH type pinned `smashline @ latest`, installed v2.0.0 and the game closed with an error at boot (2026-11-19). Never point a type at `latest` Smashline without checking what the pack was built against. The types still differ on the card (Competitive takes Smashline from the Online Deluxe package, TR4SH from HDR-Development), and a gameplay pack must never sit on an online card. Three mechanisms make a type switch safe:

- **Source stamps** — `<SD>/ultimate/.smash_night.json` (`read_sd_stamps` / `write_sd_stamp`) records the repo @ ref each plugin (and `"skyline"`) was
  installed from. `_wanted_source(name)` says what the active Setup wants; `stamp_mismatch` flags a differing copy in the Setup check so Provision reinstalls
  it. No stamp = assumed stock (so existing cards aren't touched) — it only mismatches when the Setup wants a non-stock source. Skyline is stricter: an
  unstamped Skyline is never replaced, a stamped one from another type is. A local-cache fallback install and a hand-placed override forget the stamp.
- **Chain logic is gated on Online Deluxe being in the Setup** (`_deluxe_active()`): only then do NRO Hook / Smashline come out of the Deluxe package.
  Never let a non-Deluxe type read `package_ships`.
- **Hosted packs — Provision never installs or removes a pack** (the user's rule, 2026-11-19: "The Provision is to set up the core and plugins, not TR4SH").
  A type's `pack` names the pack it *hosts* (`SETUP_PACKS`; TR4SH: GameBanana mod 372158, an SD-overlay archive of six `ultimate/mods` folders +
  `libcss_preserve.nro` + `manual_html`). The pack is an ordinary profile mod: Packs tab → Download ▾ into a profile → Load to SD, which goes through
  `install_to_sd` → `_install_sd_overlay` (the hygiene strips were checked against TR4SH 1.46 and remove nothing). What the Setup side does: the hosting
  type keeps the pack's plugins (`KNOWN_PLUGINS` entries with a `pack` key get no row and are not flagged; every other type removes them like any stray
  plugin); the Setup check has an **information-only** "<pack> pack" row (`fixable: False`) — "On the card" / "Not on the card — Load to SD the profile
  '…'" under the hosting type, and a red "can't run it — the game will crash at boot" row when the pack sits on a card whose Setup is another type;
  `_provision` ends with `_offer_profile_after_provision()` — the **"Select a profile to load"** dialog (for every type, not just TR4SH): the saved
  profiles by name with their mod counts as card-style rows (the list grows with the number of profiles and only scrolls past about two thirds of the screen height; its height is measured from the drawn rows, because row height depends on display scaling), click one then **Confirm** (loads it via `_load_profile(name, confirmed=True)`, no second question) or
  **Skip**. Profiles carrying the type's hosted pack sort first ("contains TR4SH Rebuffed"); a profile carrying a pack the card's type can't run is
  greyed and can't be confirmed. The Provision confirmation says up front that the pack comes from a profile.
  Profile-sync support for multi-folder packs: `_scan_mod_folders_by_id` (all folders of a mod id — `_scan_installed_mod_ids` keeps only one) drives
  removal, `_remove_pack_extras` deletes the pack's plugin + atmosphere extras when it leaves the card, and an overlay install (`overlay_parent` in its
  meta, `_is_overlay_install`) counts as "unchanged" so it isn't re-copied on every sync. `_find_slot_conflicts` skips a hosted pack's folders
  (`setup_pack_folders`).

- **Pack versions** (the 2026-11-19 crash: the cache held `tr4sh_rebuffed_144_essentials.zip`, so "TR4SH v1.46" installed 1.44 — an old `plugin.nro` plus
  two stage plugins its authors declare broken on 13.0.5). The mod cache is cache-first forever, which is wrong for gameplay packs:
  `_refresh_stale_pack_caches` (Load to SD pre-flight, `mod_type == "modpack"` only) drops a cached archive whose file name is no longer what GameBanana
  serves and forces a reinstall; `_do_install_to_sd` records the archive name in `.gb_meta.json` (`archive`); `_overlay_install_current` only calls an
  overlay install "unchanged" when that equals `cached_archive_name()` (no record = outdated, replaced once). `_install_sd_overlay` records every file it
  lays outside `ultimate/mods` as `overlay_files`; the sync's removal and **Remove Installed Profiles** delete those (never exefs or a Setup-managed
  plugin), and `SETUP_PACKS[...]["retired_plugins"]` names old-version plugins to delete for cards installed before the record existed.
- **Half-installed packs** (2026-11-19: the Setup check said "Not on the card" while Load to SD said "1 unchanged" — the card held three of TR4SH's six
  folders, the main one missing and Stages at 500 of 782 files). Cause: `_preflight_recheck_cached_archives` applied its *skin* heuristics to the pack
  (bloated `config.json` → "force reinstall"), so a sync started removing and re-copying half a gigabyte, in silence, and was interrupted. Now:
  (1) those heuristics, the cache strips, `_post_install_sanity` and `_sweep_mods_hygiene` all **skip overlay installs / modpacks** — a gameplay pack is
  left as shipped; (2) `_overlay_install_current` also checks the pack is **complete** — every folder in `overlay_subs` present with at least 97 % of the
  `files` count recorded at install (falling back to the cached archive's layout for copies made before that was recorded), plus the known pack's
  marker; (3) `_install_sd_overlay` writes the `.gb_meta.json` files **only after every sub-mod is copied**, so an interrupted install leaves untracked
  folders the next sync overwrites, never a half pack that reads as installed; (4) the copy prints progress (`_copytree_progress`, a line every 150
  files, and "Removing: …" before each slow delete) so a ten-minute pack copy no longer looks like a hang.
- **Stray plugins**: the Setup check lists any `.nro` in `skyline/plugins` that is neither a Setup plugin, nor shipped by the Online Deluxe package, nor
  recorded by an overlay mod on the card (`overlay_plugin_files_on_card`) as "Stray plugin — removed on Provision" (`remove:<file>`). This is what makes
  a non-clean Provision trustworthy; don't relax it without a reason.
- The Setup tab's third button is **Remove Installed Profiles** (was "Clear All Cosmetics"; `_clear_all_mods_confirm` / `_do_clear_all_mods`): every
  mod folder plus the overlay-laid files, never the Setup's core or the profiles saved on the PC.

**Choosing a Setup (since 2026-11-19, supersedes the "chooser combobox" described under layer 8):** the Setup tab's strip has no combobox, no "selected Setup" label and no tick in the Provision ▾ menu — **there is no selected/active Setup in the UI**
(user, 2026-11-19: a tick "gives the impression the provision is completed"). The tab reflects the *card*: `card_provision_state()` reads the
`provisioned` record `_provision` writes into `<SD>/ultimate/.smash_night.json` (`write_sd_provisioned`: Setup name + type), or, for a card provisioned
before the record existed, infers the type from the plugins on it (Online Deluxe → Competitive Online, Smashline without it → TR4SH Rebuffed, ARCropolis
alone → Skins Only). With no card or nothing provisioned, `_render_unprovisioned` shows **no Core Components / Setup Plugins / SD Health sections at
all**, just "Nothing provisioned on this card yet" and a pointer at Provision ▾. Otherwise `_bind_setup_to_card` measures the checks against the Setup
the record names (if it still exists with that type), else any saved Setup of that type, else the bare type (`_card_type`). `_active_setup` /
`gb_setups.json`'s `active` survive only as internal plumbing set at provision time; `_refresh_setup_chooser` is a no-op hook. The strip's top line is
just Manage Setups…. The action strip is **one row of three buttons: Provision ▾ | ⚡ Inject Payload ▾ | Other Actions ▾**. **Provision is always the
clean one** (user's decision, 2026-11-19: "provisioning unclean can cause issues or false positives") — there is no non-clean Provision button and no
separate Clean Provision button. Provision ▾ is a dropdown (`_popup_setup_menu`) listing every saved Setup with its type; picking one goes through
`_clean_provision_confirm(name)` — the two-step format warning, naming the Setup, spelling out that the format also erases games / updates / DLC stored
on the card (the Nintendo folder), and noting that a hosted pack is not installed — and the Setup becomes active only after both steps; then
`_clean_provision` formats and runs `_provision`. Nothing is written without that confirmation. In-place repair still exists per component (each check
row's fix button → `_fix_component`) and as Other Actions → Update ALL plugins; **Remove Installed Profiles…** lives in Other Actions too. Manage Setups' **Save** button commits and closes the dialog (`_save_and_close`); the toggles, Sources… and Duplicate still save in place.

When saving a Setup, store only the user's own source overrides (`strip_type_sources`) — baking a type's rows into `sources` would leave them behind on a
type change. To add a type, add it to `SETUP_TYPES` (and `SETUP_PACKS` if it owns a pack); nothing else dispatches on type names.

## Ball Drop (physics game over the Log) and the job header

`BusyPhysics` (above `TextRedirector`) does two independent things that share one `after`-driven tick loop on the Tk thread:

- **Job header** — while a long job runs (Load to SD, Provision, Update ALL plugins, a single install, Remove Installed Profiles: `_long_job_title`
  decides; `_run_async` calls `_busy_fx_begin` / `_busy_fx_end`) a one-line header above the Log shows the job name and an elapsed clock, appearing only if
  the job is still going after 1.5 s and ending on "✓ Finished — m:ss" for 2.5 s (`start` / `finish` / `hide`). This is the "it hasn't hung" signal.
- **Ball Drop** — the game. It is **never started automatically**: the **Ball Drop** button next to the Log's Clear starts it and turns into **Stop Ball
  Drop** (`toggle_game` → `start_game` / `stop_game`, `on_game_change` repaints the button). There is no "Disable fun effects" checkbox any more (the
  button replaced it; the old `disable_fun_effects` setting is ignored).

The game: small balls (13–23 px — the user tried larger and preferred these; more of them on a bigger Log) fall **on top of the Log text** under gravity that points straight down (`SWAY` 0 — it used to sway ±35° so the pile sloshed, until the user asked why the balls "move so much on their own"; with `AIR` drag and the `REST` threshold, below which a contact doesn't bounce, they now settle and move only when hit), with elastic ball-to-ball collisions and sparks on hard hits; one ball wears the app emblem (`icons8-super-smash-bros-96.png`, shipped
via `build_release.py` RESOURCES). Left-drag grabs and flings a ball; double-click a ball for a shockwave. **The right mouse button is a bow** (it replaced a baseball bat on 2026-11-19 — there is no bat code left). Press and hold: the bow is planted at
that point and stays there (`_bow_press`); dragging away draws the string back, slingshot-style, so the arrow points opposite to the pull
(`_bow_aim`); a **dotted line shows the path the arrow will fly** (`_arrow_path`, drawn by `_bow_draw` from a pool of `PATH_DOTS` ovals — it turns
orange when the path meets the emblem ball); releasing looses a **flaming arrow** (`_bow_release` → `_arrow_spawn`). The further the pull (up to
`BOW_MAX_PULL`), the faster the arrow (`ARROW_VMIN`…`ARROW_VMAX`) and so the flatter its arc; under `BOW_MIN_PULL` nothing is shot. An arrow in flight
is **unstoppable by ordinary balls**: `_arrows_step` moves it under gravity only and shoves every ball it touches aside (the arrow's own velocity is
never changed — tested: its course with eight balls in the way differs from the empty-room course by 0.000 px), which is what makes the dotted path
truthful. The one thing that stops it is the **emblem ball**: that sets off `_explode` (three rings racing outward, a burst of sparks, a boom, every
other ball thrown hard away, scaled by the arrow's speed) and the arrow bounces off, tumbles down (`_arrow_drop`) and lies on the floor. Arrows that reach the floor **or a side wall stick in it** at the angle they arrived; **every spent arrow is solid** — in a wall, stuck in the floor or lying on it (`_arrow_ground` stores its shaft in `seg`) — and `_arrow_perches` keeps every ball out of the shafts each substep: balls land on them, bump over them or are turned aside, never pass through. A grounded arrow is drawn once (`drawn`), not every frame. Each remembers what it is stuck in (`anchor`: left / right / floor); when the Log changes size `_step` calls `_resized`, which moves right-wall arrows with that wall and floor arrows with the floor (resizing the window smaller used to leave them hanging in mid-air) and pulls anything that would fall outside back in. **At most `MAX_GROUND` (10 — the user tried 7, 50 and 20) spent arrows stay** — `_arrow_ground` clears the
oldest. A wall or the floor only stops an arrow moving *into* it (the string can be drawn back past a wall, so an arrow may start outside the Log).
An arrow that struck the emblem ball (`struck`) **smokes for `SMOKE_SECS` (5 s) once it lands** — grey puffs (`_smoke`, `self.smokes`) that rise, sway, swell and fade, thick at first and thinning out. Flames are short-lived upward-drifting sparks (`_flame`, `lift`), on the nocked arrow and trailing a flying one; a grounded arrow is doused. The bow
and arrows are sized by the display scaling (`_ui`, from `winfo_fpixels`), the balls are not. The step uses 8 substeps while an arrow is in the air.

Sounds (`_boink`): quiet synthesized blips on harder bounces (pitch by ball size), a thwack in four loudness steps when an arrow ploughs into a ball, the bowstring's twang,
and the explosion's boom — tiny WAVs generated once under `%LOCALAPPDATA%\SmashNight` and played with `winsound` (async, one at a time, rate-limited; a
crack is never swallowed by a boink, a boom is always heard and rings out). Silent when Disable sound effects is ticked.

How it is drawn: the balls live on a borderless Toplevel laid exactly over `self.log` with `-transparentcolor` (`BusyPhysics.KEY`), so everything but
the balls is see-through *and click-through* — the Log stays scrollable. Three things that are easy to break: (1) Tk ignores `transient()` on an
override-redirect window, so the layer is made an **owned window of the app at the Win32 level** (`SetWindowLongPtrW(..., GWLP_HWNDPARENT, ...)`) —
without that it drops behind the app on the first click; (2) `_place()` re-reads the Log's screen rectangle every frame so the layer follows window
moves, resizes and the pane sash; (3) right-button events are bound on the Log *and* the canvas, because an "empty space" right-click falls through
the see-through layer onto the Log (same coordinates). A frame costs about 1.5 ms; any exception in the game stops the game, never the job.

Testing it from a script: drive it under `mainloop()` (worker threads call `root.after`), screenshot with
`ImageGrab.grab(..., include_layered_windows=True)` (a colour-keyed window is otherwise missing from the capture), and test the bat's dynamics by
running `_step` against a fake canvas and a fake `time.perf_counter` (see how the bow was verified) — a live window gets the user's real mouse mixed into the test, and the balls may not have settled.

## Local mods

Mods that never came from GameBanana (a voice pack from `voice_packs/`, a friend's folder) are first-class profile entries: the Profiles view's
**Add Local Mod…** button (`_add_local_mod_ui`) drops a menu of the folders already in `local_mods/` plus "Browse for a new folder…" (`_browse_local_mod`); `find_mod_content` checks it is a mod, `register_local_mod` copies it to
`local_mods/<name>/` (git-ignored, the canonical copy) and returns an entry with `mod_id = "local_<name>"`, `mod_type = "local"`, `character` guessed from
`fighter/<x>/` or a `vc_<x>`/`se_<x>` bank name, which `_pick_profile_and_add` puts in a profile. The profile sync needs nothing special: `_do_install_to_sd`
spots the `local_` id, re-stages the folder into `MOD_CACHE_DIR/<id>/extracted/` (`stage_local_mod_in_cache`, so Clear Cache can't lose it) and takes the
stage branch (plain copy, no slot logic) with `.gb_meta.json` carrying the id, so `_scan_installed_mod_ids` sees it and removal works like any mod.
`_download_mod_archive` refuses `local_` ids. Never give a local mod a numeric-looking id.

## Big picture

`smash_night.py` is structured as a long script of module-level helpers followed by a single giant `GameBananaBrowser(tk.Tk)` class that owns all UI. Section banners (`# ── SECTION ──`) are the navigation aid — use `grep -n '^# ──'` to jump.

### Module-level layers (top-to-bottom in the file)

1. **SD-card / path constants** (lines ~70–260). `SD_CARD` is auto-detected from removable + Switch-marker drives; `_apply_sd_drive()` mutates a set of derived globals (`ARCROPOLIS_MODS`, `ATMOSPHERE_CONTENTS`, `PLUGINS_DIR`, `EXEFS_DIR`, `ROMFS_DIR`, `PAYLOAD_SEARCH_PATHS`) when the active drive changes. Anything that touches the SD must read these *globals* (not cache them at import time).
2. **Provisioning profiles + GitHub release map** (lines ~220–290). `PROVISIONING_PROFILES` (Competitive / Skins Only / Custom) layers extra `.nro` plugins on top of `CORE_PLUGINS`. `GITHUB_REPOS` is the source of truth for what to download and how to recognize each asset by filename. Atmosphere has an "unofficial" path: when a new firmware ships, the official repo lags, so we fall back to `UNOFFICIAL_ATMOSPHERE_FORK` (`zandercodes/Atmosphere-unofficial`) for builds of the `22_support` branch, and then to a local zip in `switch_setup/downloads/`.

   ARCropolis has the same lag problem in a sharper form: it hard-refuses any Smash version but the one it was built for, and a new Smash update can leave the fix on `main` unreleased for days (13.0.5 shipped; v4.0.9 was still a 13.0.4 build). `find_local_arcropolis_override()` looks in `switch_setup/downloads/` for a hand-placed `libarcropolis.nro` (or a zip containing one, e.g. a CI artifact) and `_download_plugin_from_github` prefers it over GitHub — which also keeps *Update All* from clobbering it. `arcropolis_required_smash_version()` reads the required Smash version out of any `libarcropolis.nro` (the refusal dialog is embedded as a plain string), and the Setup tab shows it as "built for Smash X" so a mismatch is visible before boot.

   There is deliberately **no nightly / CI-artifact path** any more (removed 2026-11-02 at the user's request: "I do a pinned version. Never nightly."). ARCropolis is always installed from a release — `latest` or a `tag:` pinned in the Setup's Sources — and a hand-placed override in `switch_setup/downloads/` is the only other way in. `github_latest_ci_artifact` / `_install_arcropolis_nightly` / `ARCROPOLIS_CI_BRANCH` are gone; the legacy `nightly_arcropolis` key in old profiles/Setups is ignored on read and dropped on save.

   The mod also reads an optional `sd:/ultimate/ssbu_online_deluxe/config.toml` (menu / offline / online-Auto render profiles, overclocker switch). Each user profile carries its own copy under `deluxe_config` (`DELUXE_CONFIG_DEFAULTS`, normalized by `profile_config()`), both profile dialogs edit it via `_build_deluxe_config_widgets()`, and Provision writes the file through `_write_deluxe_config()` when `deluxe_config_status()` says the card differs. `parse_deluxe_config_toml()` is deliberately tiny — it reads the shape upstream documents and we write, and returns None (→ "rewritten on Provision") for anything else rather than guessing.

   `KNOWN_PLUGINS` is the plugin registry — dispatch on it, not on `LOCAL_PLUGINS` (that's only a fallback *cache* of `.nro` files bundled in this repo, and most plugins have no bundled copy). Two flags matter:
   - `dependency: True` — installed and removed alongside the mod that needs it, never toggled on its own. `expand_plugin_deps()` adds them; `selectable_plugins()` hides them from the profile editor.
   - `deprecated: True` — never installed, but still listed so a card provisioned by an older build is recognised and cleaned up. `RETIRED_PLUGINS` maps each to its replacement, and `migrate_retired_plugins()` translates at *read* time inside `profile_config()` — `gb_profiles.json` is never rewritten, so an older build of the app can still read it.

   **SSBU Online Deluxe** (`saad-script/ssbu-online-deluxe`) replaced Latency Slider DE + Less Delay when SSBU 13.0.5 broke both. It is not a standalone `.nro`: `ONLINE_DELUXE_DEPS` lists six plugins it needs, it pins its *own* Skyline build (`_install_skyline()` takes `main.npdm`/`subsdk9` from the mod's release, because upstream warns the current skyline-dev release crashes with it), and it wants a boot2 overclock sysmodule under `OC_SYSMODULE_TITLE_ID` (`oc_sysmodule_dir()`, `_install_oc_sysmodule()`). A partial install is a guaranteed crash on boot — never let one of these pieces be installed without the others.

   `extract_release_file(repo, filename, dest)` is the single install path for every plugin: it prefers a release asset named exactly `filename`, else searches inside every `.zip` asset for a member with that basename. Match on the *payload* filename, never the asset name — upstream renames release archives between versions far more often than the files inside them. Release archives are cached per run in `_RELEASE_ZIP_CACHE` (the Online Deluxe zip supplies seven files); call `_clear_release_cache()` when a provision/update run finishes.

   **Quickplay build.** Upstream deliberately enables its latency / render-profile controls only in Arena, Local Online and Nextendo-Quickplay (`is_valid_online_mode()` in `src/net/mod.rs`, plus the status store in `online_melee_any_init`). `vendor/ssbu-online-deluxe/` is upstream at a pinned tag with those gates removed — five changes across `src/net/mod.rs`, `src/render/profile.rs` and `src/ui/overlay/mod.rs`, each marked `// Fork:` (the two mode gates; `online_bg_matchmaking_init` no longer resetting Quickplay to Offline during the post-CSS opponent search; `match_init` treating any valid online mode as an online match even before the pia session reports connected — without those two the match started on the *offline* profile, Vanilla; and `reconcile_enforced_vanilla()`, which restores vanilla *resolution* once per match when the closed-source ssbusync has forced the pipeline back to vanilla on Nintendo's servers, and tags the overlay's NetProfile cell "(server)" — ssbusync's override cannot be disabled from the mod, so the label is made honest rather than the profile made to stick; and `suggested_delay_frames()`, which appends "~Nf" to the overlay's Ping cells); its `VENDOR_INFO.md` records the tag/commit, each change, what was dropped from the tree, and the update procedure. It is deliberately a vendored *copy*, not a fork or a patch file, so the mod's Rust can be edited from chat and the build depends on nothing outside this repo. `.github/workflows/build-online-deluxe.yml` builds it in the `jugeeya/cargo-skyline` container on any change under `vendor/ssbu-online-deluxe/` and **commits the resulting `.nro` to `smash_mods/quickplay/`** (with `BUILD_INFO.txt`). `_download_plugin_from_github` *used to* prefer that file (`ONLINE_DELUXE_QUICKPLAY_BUILD`) over upstream's release for the `.nro`; since 2026-11-02 it doesn't — the Online Deluxe source is the Ivan Elite fork (see layer 8) — Skyline, ssbusync, nx-over and the sysmodule are not in the source and keep coming from upstream's release via `ONLINE_DELUXE_REPO_KEY`. `_NRO_TO_REPO[ONLINE_DELUXE_NRO]` still names upstream so the Setup row's version hint tracks the real project. If the file is absent, install falls back to upstream's `.nro`. `lib/libimgui_smash.a` (16 MB) is a required link blob, not an accident. This build cannot be produced in the Claude sandbox (no Docker daemon); the workflow is the only build path.
3. **GameBanana category tables** (~290–560). `FIGHTER_CATEGORIES` (skins, cat 3330), `STAGE_CATEGORIES` (cat 6089), `OTHER_CATEGORIES`, gameplay subcats. `MOD_TYPE_BY_CATEGORY` collapses a GameBanana subcategory id onto a coarse type (`skin` / `stage` / `moveset` / `modpack` / `mechanics` / `balance` / `ai` / `parameters` / `effect` / `music` / `ui` / `other`). Only `skin` mods drive the slot-picker UI (`SLOT_AWARE_MOD_TYPES`).
4. **File-conflict / slot classification** (~700–900, ~2360–2840). `_classify_mod_path(rel_path)` is the most important helper here: it returns `(fighter, slot)` for a relative file path inside a mod and is shared by:
   - `detect_file_conflicts()` — distinguishes *real* per-slot collisions (must remap) from shared-resource overlaps that ARCropolis layers last-write-wins (no prompt).
   - `compute_touched_slots()` — populates `gb_touched_cache.json` after install.
   - `simulate_resolved_layout()` / `diagnose_freeze_risks()` — pre-flight scan that mimics what SSBU's file resolver will see and flags freeze risks (orphan portrait/body, motion without model, multi-mod collisions).
5. **GameBanana API** (~930–1110). `api_search_mods` is the single search path for browse / stages / "Other". `api_get_mod_files` and `api_get_mod_images` round it out. All over `https://gamebanana.com/apiv11`. Network is `requests` with `verify=False` and urllib3 warnings suppressed.
6. **Install pipeline** (~1620–2240). `extract_archive` → `find_mod_content` (locates the romfs root inside the extracted tree) → `install_to_sd` (copies to `<SD>/ultimate/mods/<name>[_cXX]`, writes `.gb_meta.json`, applies optional `slot_map` or `target_slot` remap). `_remap_slots` / `_apply_slot_map` rename `cXX` directories *and* slot-bound filenames (UI bntx, sound nus3audio) consistently. `_repair_multislot_artifacts` cleans up GameBanana archives that ship malformed dirs like `c00, c03`.
7. **RCM injection** (~1640–1830). `inject_payload(smash_exe, payload_path)` has a careful three-branch strategy: (1) if already admin, run subprocess directly; (2) if `EnableLUA=0`, bail with a message pointing at `Run_As_Admin.bat` (Windows can't elevate at all in this state); (3) otherwise, elevate via `ShellExecuteEx` with `SEE_MASK_NOCLOSEPROCESS` and wait on the process handle. Do **not** replace this with PowerShell `Start-Process -Verb RunAs` — signed-script enforcement and ExecutionPolicy break it intermittently with a misleading "operation was canceled by the user" error.
8. **Profiles, Setups + favorites persistence** (~3260–3620). Three related concepts:
   - **User profiles** (`gb_profiles.json`) — curated lists of mods plus `wifi_safe`. These are *cosmetic* only now: the Profiles tab's "Load to SD" delta-syncs a profile's mods onto the card. Older entries still carry core keys (`template`, `unofficial_atmo`, `nightly_arcropolis`, `plugins`, `deluxe_config`); `profile_config()` keeps tolerating them (`plugins=None` = "inherit from template", `[]` = "explicitly none") but nothing reads them for provisioning any more.
   - **Setups** (`gb_setups.json`, `{"active": name, "setups": {name: {...}}}`) — saved *core* configurations the Setup tab deploys: plugin set, fork vs. official Atmosphere, Sources, Online Deluxe `config.toml`. `setup_config()` normalizes one (it is `profile_config()` minus `wifi_safe`). `load_setups()` migrates once: every profile carrying core keys becomes a Setup of the same name, identical configs collapsed, else a single default "Tournament" Setup. The active Setup is persisted in the file; `_active_setup_name()` / `_active_setup_cfg()` / `_set_active_setup()` are the accessors, and `_active_plugin_list()` / `_active_deluxe_config()` read from it. The Setup tab has a Setup chooser combobox, a "Manage Setups…" dialog (`_open_setup_dialog`, with the card-matches-setup banner and a Provision Card button), and Provision runs `_provision_setup(name)`. `SETUP_NOUN` is the user-facing name of the concept; change it there if "Setup" gets renamed. Each Setup can also override **Sources**: `sources` is `{key: {repo, ref}}` for every `GITHUB_REPOS` key; `ref` is `latest`, `prerelease`, `tag:<tag>` or `branch:<name>`. Three rows have non-trivial stock values (Atmosphere, Smashline, Online Deluxe) (`source_default`): **Atmosphere** is `OFFICIAL_ATMOSPHERE_REPO @ latest` (official 1.12.1 supports FW 23.0.0; the fork's 23_support builds are older) — pointing the row at any other repo makes `_resolve_unofficial_atmosphere` prefer that fork's support-branch builds (`ATMOSPHERE_SUPPORT_BRANCH`, now `23_support`, when the ref isn't a `branch:`) when newer than official stable, which is the old fork-Atmosphere flag; **ARCropolis** has no special stock value any more (`latest`; pin a `tag:` to hold a version — there is no CI-build path); **Smashline** is pinned to `tag:v1.6.8` because Smashline 2.0.0 (2026-10-28) breaks plugins built against 1.x, SSBU Online Deluxe included. `setup_config()` derives `unofficial_atmo` from the Atmosphere row and translates the legacy boolean keys and the retired `atmosphere_fork` row into an Atmosphere row on read (a legacy `unofficial_atmo: True` with no row now simply means stock, i.e. official); Manage Setups drops the legacy keys on save. `_active_setup_cfg()` mirrors the active Setup's overrides into the module-level `_SOURCE_OVERRIDES`, and every download / version-check path reads through `source_repo()` / `source_ref()` / `source_release()` / `source_asset()` instead of `GITHUB_REPOS` directly (`github_release_for(repo, ref)` does the tag / prerelease lookups; `source_asset` reports official stable for a branch ref on Atmosphere / fusée and the release for one on ARCropolis). **SSBU Online Deluxe's stock source is a fork**: `IvanSS22030/ssbu-online-deluxe-ivan-elite @ tag:v1.4.2-ivan` (upstream 1.4.1 with the latency / render-profile controls enabled in Nintendo's Quickplay and Elite Smash). That replaced the earlier approaches (the vendored `vendor/ssbu-online-deluxe` build and a short-lived per-Setup "patches" mechanism — both gone from the install path; the vendored tree remains in the repo (its Actions workflow was removed 2026-11-19 — this repo deliberately uses no GitHub Actions) but nothing reads `smash_mods/quickplay/` any more). A fork release is a whole SD layout, so the app indexes the source's package (`source_package_index`, cached per run with the release zip): chain dependencies the package ships are installed from it (`_download_plugin_from_github`, `package_ships`) and judged against it in the health check; bundled-only dependencies the fork leaves out (`_NRO_TO_REPO` → the Deluxe key, e.g. nx-over, which Ivan's build removes) are dropped from `_active_plugin_list()` so they are neither installed nor reported missing; sysmodules are installed under whatever title ids the package uses (`package_sysmodules`, `sysmodule_title_ids` — Ivan ships sys-clk under `00FF0000636C6BFF` plus `config/sys-clk/config.ini`, instead of upstream's overclocker under `OC_SYSMODULE_TITLE_ID`), and `_remove_oc_sysmodule` / the health row follow the same ids. When the package ships a sysmodule but not upstream's `OC_SYSMODULE_TITLE_ID` (`package_overclocker_external()`), the mod's built-in overclocker has no service to reach and shows "Unable to load overclocker service" at launch, so `effective_deluxe_config()` forces `overclocker = false` in the config.toml this app writes (`_active_deluxe_config()` returns the effective config; Manage Setups labels the checkbox as overridden). `package_overclocker_external()` answers from `_PACKAGE_INDEX_CACHE` only when called on the Tk main thread (dialog builds, status labels) — indexing the package can download the release zip, which froze Manage Setups while a GitHub check was running; worker threads resolve it for real. Point the row back at `saad-script/ssbu-online-deluxe @ latest` to get upstream's package. Edited from the Sources… button inside the selected Setup's form in Manage Setups (`_open_sources_dialog`, which shows repos as full github.com links and sizes itself to fit every row); `normalize_repo_text` accepts a link or `owner/name`, and only entries that differ from the defaults are stored (`normalize_sources`). Manage Setups has no Provision button — the Setup tab's Provision deploys the chosen Setup; name edits commit with its Save button. It also holds the **GitHub token** box (`save_github_token` / `github_token_status`, writing the git-ignored `github_token.txt` that `_github_token()` reads; env vars `GITHUB_TOKEN` / `GH_TOKEN` still win). There is no Manage Profiles dialog and no "set active" anywhere: the Create Profile dialog sets name + Wifi-Safe, cards have Duplicate / Delete, and the profile a download lands in is picked per click from each card's **Download ▾** dropdown (`_popup_profile_menu`, which also offers "Create Profile…"); skin cards' Download ▾ opens the 3D / drag-to-slot dialog (`_view_model`; drops write the profile immediately, but the dialog snapshots `gb_profiles.json` on open (`ctx["profile_snapshot"]`) and `_on_install_window_close` restores it unless Save set `ctx["saved"]` — Close / the X mean cancel), while stage / pack / other cards (and non-slot Favorites) have a single registered Download ▾ that installs directly (`_register_install_button`, blue, flips to "✓ In Profile ▾"); that pick becomes `_profile_mode_target` via `_set_profile_target`, which the slot pickers show on their own clickable "Profile: <name> ▾" line above the "Install to:" slot row (two lines so c00–c07 never clip; the circled "?" to the right of the slots (`_add_help_circle`) shows `SLOT_COLOR_HELP` as a left-aligned tooltip or window: grey empty / green taken by another skin / blue this skin). The Setup tab's chooser (unlabelled combobox + Manage Setups… button) and action grid live in `_setup_actions_frame`, a strip packed *above* the results canvas so it never scrolls; the pass/fail summary and check rows scroll beneath it. The grid is 3 equal-weight columns filling the pane: row 0 Provision / red Clean Provision (wipes the SD after confirmation) / Clear All Mods; row 1 Other Actions / Inject Payload (spanning 2 columns); the pass/fail summary heads the scrolling check list beneath the strip. Check rows are strictly one line each (`_add_check_row`: name on the left, the detail right-aligned, newlines collapsed to ` · `; the detail is a flat read-only `Entry`, not a label, so a long one scrolls left/right (drag, arrows, Shift+wheel) instead of being truncated). `_clean_provision` waits for Windows to re-mount the card after the format (`_wait_for_sd`) and `_provision` re-takes its health snapshot while the SD Card row fails — acting on a snapshot taken before the re-mount installed nothing, which was the "first Clean Provision stays red, second works" bug. The window opens sized so this list needs no scrolling: `_build_ui` estimates the height from the active Setup's component count, and `_fit_window_to_setup()` grows the window to the real content height exactly once (first Setup render, `_setup_fit_done`), both capped at the screen height; later repaints (provision, re-check) never resize the window. Width is ~45% of the screen (min 1600, capped to the screen) and the results pane stays a fixed 860px so extra width goes to the Log; the window is never maximized or shrunk automatically. There is no RCM status label any more — the inject button's colour carries the state, and `_rcm_device_label` / `_rcm_status_label` survive as never-gridded labels because `_rcm_poll_update` writes to them. **Inject Payload ▾** is a dropdown, not a window (`_popup_payload_menu`): it lists every payload `_discover_payloads()` finds (bundled `payloads/`, the SD's `bootloader/payloads` and `atmosphere`, plus a custom Browse… pick), marks the current one (`_current_payload_path`: last picked, else `find_payload()`'s hekate-first preference), and picking an entry injects immediately when a Switch is in RCM mode (button green) or just remembers it otherwise; the menu has no status line — the button colour is the status. The button is always enabled; `_open_payload_dialog` survives only as an alias that opens the menu. `_refresh_setup_chooser()` updates the chooser after a rename / new / delete without re-running the checks. The GitHub version table `_do_setup_fetch_github` builds is cached on the instance (`_gh_latest_cache`, `_GH_LATEST_TTL` = 10 min, keyed by the active sources via `_gh_cache_key`) so the many `_show_setup()` re-renders don't re-fetch; a rate-limited/offline run is never cached, and Other Actions → Refresh Setup Checks sets `_force_gh_refresh` to bypass it.
   - **Favorites** (`gb_favorites.json`) — flat per-mod stars surfaced in the Favorites view.
9. **`GameBananaBrowser`** (line 4037 onwards). One class, ~9000 lines, ~230 methods. The active view is tracked by `self._active_view` (`browse` / `stages` / `packs` / `other` / `favorites` / `installed` / `profiles` / `setup`). Dialogs are centred over the window they came from with `_place_near(win, parent)` (Manage Setups over the main window, Sources over Manage Setups, Create Profile / validate report / pick-profile likewise) — call it after setting the dialog's size; without it Tk drops every Toplevel at the screen's top-left. The header's right-hand button row is Drive ▾ / 📂 Folder (`_open_app_folder`, opens the app directory in Explorer) / Diagnose / Eject. The tab bar is two `LabelFrame` groups, *Browse* (Skins / Stages / Packs / Other / Favorites) and *Deployment* (Installed / Profiles / Setup). UI rebuilds itself by clearing `self.results_inner` and repopulating from the relevant data source. Long-running work (downloads, installs, validation, audits) goes through `self._run_async` so the Tk main loop stays responsive; UI updates from worker threads must be wrapped in `self.root.after(...)`.

### State on disk

- `%LOCALAPPDATA%\SmashNight\settings.json` — tiny flat key/value app settings (`load_settings` / `save_setting`, `SETTINGS_FILE`). Per Windows user and *outside* the app folder on purpose: the folder is a shared/synced copy, and one person's choices must not follow it. A legacy `gb_settings.json` in the app folder is still read and removed on the next save. Only key so far: `mute_sounds`, set by the "🔇 Disable sound effects" checkbox next to the Kid Friendly lock; `sounds_enabled()` gates every clip (`play_clip`, the splash sound).
- `gb_profiles.json` — user mod profiles.
- `gb_favorites.json` — starred mods.
- `gb_audit_cache.json` — adult-only audit results, keyed by search params.
- `gb_touched_cache.json` — `{mod_id: {touched: [[fighter, slot], ...], ts: ...}}`. Re-populated on every successful install via `record_touched_for_mod`. Used by profile-validation to pre-flight-detect cross-character slot collisions (e.g. a mod tagged "Birdo" that secretly replaces `fighter/yoshi/c02/`) **without** re-extracting archives.
- `gb_sets.json` — legacy profile file. `load_profiles()` migrates it to `gb_profiles.json` once if the new file is missing.
- `.mod_cache/<mod_id>/` — extracted mod archives, kept around so we can re-render previews / re-install without re-downloading.
- `.render_cache/` — PNG thumbnails of 3D model previews produced by `render_model_preview` (uses `pyrender` + `trimesh` + `ssbh_data_py`; gracefully no-ops if those packages aren't installed).
- `photos/chit-cartoon.png` (captioned by `_draw_splash_caption`, 22 pt white/black-outline, semi-transparent) + `sounds/back-to-it-then.mp3` — the startup splash (`show_splash()` in the Splash screen section above `main()`): borderless centred photo, clip played through Windows MCI (`_mci`, decodes MP3 natively, no ffmpeg/winsound), shown for at least `SPLASH_MS` and kept up *until the main window is painted*: `show_splash()` fades it in and returns a handle, `main()` builds the UI behind it and schedules `_reveal` with `root.after(<time left of the minimum>)`, which deiconifies + `update()`s the window and only then calls `close_splash()` — never a moment with nothing on screen. The reveal must run *inside* `mainloop()`: the UI build starts worker threads that read Tk variables (`_do_search` → `fighter_var.get()`), and Tk raises "main thread is not in main loop" for those until mainloop is dispatching — never pump Tk (`update()`, `wait_variable`) between `GameBananaBrowser(root)` and `mainloop()`. It drops `-topmost` after the fade so the SD-drive prompt or an error box can't hide behind it. Nothing slow may run before it: `trimesh` / `pyrender` are `_LazyModule` stand-ins (imported on first use, or by the `_prewarm_3d()` thread `main()` starts just before the splash — importing them at the top of the file cost ~5 s on a cold start), `_ensure_start_menu_shortcut()` runs after the splash is up, and `launcher.py` caches the compiled `smash_night.py` under `%LOCALAPPDATA%\SmashNight\app_code_*.bin` (`_app_code`, keyed by path/size/mtime/bytecode version). Every piece is optional; a missing file just degrades the splash. `play_clip(path, alias, restart)` is the general fire-and-forget MP3 player built on the same MCI call. MCI devices are per-thread and hold the file open while the alias exists, so each clip runs on its own short-lived helper thread (open → play → wait for the end or a stop Event → close); callers on any thread never block, nothing stays locked, and no Tk call is made from a worker. `alias` is a channel name tracked in `_CLIPS` (`clip_playing`, `stop_all_clips` for the mute checkbox); every sound has a per-file cooldown (`SOUND_COOLDOWN_S` = 120 s, `_LAST_PLAYED`): the same clip is skipped for two minutes after it last played, so bursts of clicking stay quiet; `sounds/chit-success-boosted.mp3` (the site's "louder" take with +4.5 dB of lossless global-gain boost on top) (`SUCCESS_SOUND`, alias `INJECT_SUCCESS_SOUND`) plays on a successful payload injection, at the end of `_provision` (which Clean Provision also ends in) and at the end of a profile Load to SD (`_load_profile`'s DONE line); worker threads schedule it via `root.after`. `sounds/do-it-lady.mp3` (`DOWNLOAD_SOUND`, `play_download_clip()`) plays at the start of `_provision` (so Clean Provision too), `_inject_payload`, `_fix_component`, `_update_all_from_github`, at the top of `_do_install_to_profile` / `_do_install_to_sd` (every card Download click, cached archive or not — except drag-drops inside the 3D/slot install dialog, which pass `quiet=True` — neither the drops nor that dialog's Save make a sound), and inside `_download_mod_archive` when a mod is actually fetched (profile Load to SD). It is deliberately *not* hooked into `download_file_to`: the Setup tab's version check and package indexing fetch files too, and the user does not count those as downloads. Own MCI alias with `restart=False`, so a burst doesn't restart it per file. `sounds/manahoars-slaughtered.mp3` (`DELETE_PROFILE_SOUND`, Sacrifice's "All of your manahoars have been slaughtered") plays in `_delete_profile` once the user confirms; `sounds/rip-ricky.mp3` (`REMOVE_MOD_SOUND`) plays when a single mod leaves a profile: the in-profile toggle on a Download button, the Remove button in the profile detail view, and clearing a slot in the install dialog. `sounds/superior-grip.mp3` (`GRIP_SOUND`) plays when a skin is first picked up (drag start, `on_press` in the install dialog), once per dialog via a `_smash_grip_played` flag on the dialog Toplevel. `sounds/chit-mmmm-yes.mp3` (`CANCEL_SOUND`) plays when a dialog closes without its Save: `wire_cancel_sound(win)` binds the Toplevel's <Destroy>, and each save/create/apply handler sets `win._smash_saved = True` first. Wired on the install (slot) dialog, Create Profile (both), the profile edit dialog, Manage Setups, Sources, the slot-map dialog and the remove-losers dialog. New dialogs with a Save should call it too. Clips the app does not reference live in `sounds/unused/`. `sounds/` also holds the other myinstants clips the user collected.
- `tools/unrar/UnRAR.exe` — RARLAB's freely redistributable UnRAR (`BUNDLED_UNRAR`), bundled so `.rar` mods extract without WinRAR; `_bootstrap_unrar()` skips the winget WinRAR install when it is present and `extract_archive` prefers it. Shipped in the release.
- `payloads/hekate_latest.bin`, `payloads/fusee.bin` — bundled RCM payloads. Search order is in `PAYLOAD_SEARCH_PATHS`; hekate is preferred because it supports any FW Atmosphere supports.
- `rcm_tools/TegraRcmGUI_v2.6_portable/TegraRcmSmash.exe` — bundled RCM injector CLI; `find_rcm_smash()` searches a few likely locations.
- `ssbh_editor/ssbh_editor.exe` — auto-downloaded by `_ensure_ssbh_editor()` from the latest GitHub release; used for the "Open in SSBH Editor" action on installed skins.
- `switch_setup/mods/arcropolis/extracted/...`, `switch_setup/downloads/...` — pre-staged ARCropolis and (optionally) local Atmosphere overrides.

### A few non-obvious invariants

- `MAX_SLOT = 16` (c00..c15) is how far to *scan* when reading a card — a c08+ mod someone installed by hand must still be seen and conflict-checked. `VANILLA_SLOTS = 8` is how far this app may *assign*: every site that picks a free slot goes through `assignable_slots()` (c00..c07), and both slot pickers render c08+ greyed and unclickable. Slots c08+ don't exist in `data.arc`; they only work with `new-dir-infos` / `new-dir-infos-base` / `share-to-added` declarations that `_regenerate_config_json` does not generate, so handing one out produces a mod that freezes at match load. Don't reintroduce `range(MAX_SLOT)` in an assigning path.
- `_regenerate_config_json` must never filter `share-to-vanilla` / `share-to-added` by disk existence. Per ARCropolis `fs.rs`, each key is a source *hash* resolved against the arc and each destination is fed to `add_shared_file` precisely when it is *not* already a file — a destination not being on disk is the designed case. Filtering on it deletes every entry and is what made reslotted skins freeze while native-slot installs (which never rewrite `config.json`) kept working. Only `new-dir-files` entries are real mod files and safe to orphan-strip.
- **ARCropolis 4.1+ is two things, not one.** Its release zip ships `libarcropolis.nro` *and* `ultimate/arcropolis/resources/` (menu layouts, `msg_menu.xmsbt`, `config.json`). Install only the `.nro` and every boot shows "ARCropolis is missing files it needs for its in-game menus" (the game still runs, so it's easy to miss). `extract_arcropolis_resources()` lays those members down from whatever archive the plugin came from (release zip, CI artifact, hand-placed zip); `_install_arcropolis_resources()` falls back to the release zip; `_download_plugin_from_github` calls it after every ARCropolis install, and the SD Health row "ARCropolis Menu Files" (`arcropolis_resources_status()`, fix key `arcropolis_resources`) reports it. Never add an ARCropolis install path that skips this.
- `WIFI_UNSAFE_MOD_TYPES` is what gates the wifi-safe profile filter. Everything else (skin/stage/ui/music) is treated as wifi-safe.
- "Slot collision" and "shared overlap" are distinct concepts in this codebase — only the former should ever surface a remap prompt to the user. `_classify_mod_path` returning `(None, None)` means "shared resource, last-write-wins, do not warn".
- When the user picks a different SD drive from the multi-drive prompt at startup, you must call `_apply_sd_drive(drive)` rather than just reassigning `SD_CARD` — there are several derived globals.
- `numpy>=2.0` removed `np.infty`, but `pyrender.Viewer` still references it. There's a shim at the top of the file (`np.infty = np.inf`); leave it in if you touch the imports.
